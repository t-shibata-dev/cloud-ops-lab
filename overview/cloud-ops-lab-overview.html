1. プロジェクトについて

  • 名称：cloud-ops-lab
  • 内容：AWSを使用して、クラウドインフラの構築・管理を行なう
  • 構成技術：AWS(EC2, RDS, S3, Lambda) / Terraform / Docker / Kubernetes / CI/CD

2. 作成した意図

  1. AWSやクラウドの概念を理解し、クラウドインフラを扱えるような能力を目指す
  2. AWSサインアップ$100＋αの無料クレジット枠の範囲でできる限り理解を深める
  3. SREエンジニアに必要な知識を得る

2.1. 学習したいこと

  • AWS
    • EC2(Elastic Compute Cloud)
      • Amazon Lightsailは拡張性・自由度が限られるためEC2を選択する
    • S3(Amazon Simple Storage Service)
    • RDS(Relational Database Service)
    • Lambda(Pythonプログラム)
  • Terraform
  • Docker
  • Kubernetes

2.2. 学習手順

  1. 手動構築で基礎固め（AWS Console）
  2. データ層の強化（RDS）
  3. コード化・自動化（GitHub + Terraform）
  4. サーバーレス自動化（Lambda）
  5. コンテナ化（Docker → Kubernetes）

2.3. 当初計画目安（1日1〜2時間）

1 EC2 + S3 + WordPress手動構築 2〜4週間
2 RDS導入・DB移行 1〜2週間
3 GitHub + Terraform 3〜6週間
4 Lambda（Python・死活監視） 2〜4週間
5 Docker 2〜4週間
6 Kubernetes 4〜8週間

3.3. 設計・実装

  • SSH(22)を開けずSSM Session Managerで運用（攻撃面の削減・IP揺れ対策）
  • アクセスキーを置かずIAM ロールで権限委譲（最小権限）
  • SGのソースをIPでなくSG参照にする
  • 手動構築 → Terraformコード化の順序（何を自動化しているか理解できる）

4. 苦労した点

  • スケジュール変更
  • AWSコンソール画面は慣れが必要
  • AWS無料クレジット枠範囲で実装
  • macOSの環境依存(Rosetta, Apple Silicon)
  • Claude週間使用制限

4.1. スケジュール変更

  • 開始前にPhaseごとにスケジュールを立てるも計画どおりには進まない
    • 新しい作業が多々発生

4.2. AWSコンソール画面

  • 基本操作がわからない
  • 多機能すぎてわからない
  • 用語がわからない
  • 発生する費用がわからない

4.3. AWS無料クレジット枠範囲で実装

  • 低コストにしたせいでトラブルが発生
    • t3.micro(1GB)でOOM発生 → t3.small(2GB)で解消

4.4. macOSの環境依存

  • M1を使用しているがTerminalがRosetta有効になっていた
    • アプリをIntel用からApple Silicon用に変更

4.5. Claude週間使用制限

  • Claudeのクレジット限界で週間規制あり
  • 「Opus 4.8 高」はクレジットの消費が激しい？ので「Opus 4.8 低」に途中から変更
  • プロモーションクレジット$100あったので助かった
    • 「Opus 4.8 高」2〜3時間で$50も消費された
